# Журнал: экран «Сюжетные линии» по макету

Макет: `docs/img/Элегантный редактор сюжетных линий.png` (источник истины по внешнему виду).
Дата начала: 2026-10-01.

Правило работы: один шаг — одно изменение — сборка — тесты — запись в журнал.
Ни один шаг не считается закрытым без `dotnet build` (0 ошибок) и `dotnet test` (все зелёные).

Фон карточек этапов (заливка): `#F7EDEA`, `#F5F0E8`, `#F0F1EE`, `#F5EFF1`.

Статус «В работе»: точка `#5F9A46`, подпись `#5F8A4A`, подложка `#EDF0E2`.

## Решения по поведению (согласованы с заказчиком)

1. Связь «сцена ↔ этап линии» задаётся **со стороны сцены** (в панели контекста сцены),
   на экране линий сцены только **отображаются** (только чтение).
2. «…» у карточки этапа — меню действий: вверх, вниз, финальный, удалить.
3. Клик по карточке этапа раскрывает её на месте; повторный клик сворачивает.
4. При выборе этапа боковая панель показывает **краткую** сводку этапа.

## План

### Этап A. Данные и контракты
- A1. `PlotLine`: `Goal`, `Status` (`PlotLineStatus`), `Notes`.
- A2. `PlotLineStage`: `Icon` (ключ иконки этапа).
- A3. DTO + `SnapshotMapper` + `BookArchitectureService` (сохранение новых полей).
- A4. SQLite: миграция схемы v2→v3 (`goal`, `status`, `notes` в `plot_line`), чтение/запись.
- A5. ZIP-формат: новые ключи линии и этапа, обратная совместимость.
- A6. Тесты: round-trip JSON ядра, SQLite, ZIP, миграция старого файла.

### Этап B. Направление связи: сцена → этап
- B1. `UpdateSceneRequest.PlotLineStageIds`; `UpdateSceneAsync` синхронизирует
  `stage.SceneIds` (единый источник истины остаётся у этапа, меняется только точка входа).
- B2. `SceneContextViewModel`: выбор линии и этапа, чипы назначений, добавление и снятие.
- B3. Панель контекста сцены в `MainWindow.axaml`: раздел «СЮЖЕТНЫЕ ЛИНИИ» с выбором.
- B4. Экран линий: чекбоксы сцен убраны, сцены показываются только для чтения.
- B5. Тесты: назначение этапа сцене и снятие, влияние на выдачу линии.

### Этап C. Палитра и стили
- C1. `Palette.axaml`: ключи макета (поверхности, акценты, чипы, поля).
- C2. `ThemePalette.cs`: те же ключи для пяти тем.
- C3. `AppStyles.axaml`: стили шапки, вкладок, карточек, точек, полей, кнопок.

### Этап D. Экран «Сюжетные линии»
- D1. Три колонки: список линий / лента этапов / свойства.
- D2. Левая колонка: заголовок, «+», пункты с точкой, подписью и «…».
- D3. Центр: шапка линии, статус, крупный заголовок, цель, «Изменить», лента этапов,
  «Добавить этап».
- D4. Карточка этапа: номер, коннектор, акцентная полоса, иконка, меню «…», раскрытие
  по клику (участники — персонаж и шаг арки; сцены — только чтение).
- D5. Правая панель: свойства линии и краткая сводка выбранного этапа.

### Этап E. Оболочка
- E1. Шапка: знак, «ScriSelf Studio», «Всё под рукой», шесть вкладок, правая группа.
- E2. `ShellViewModel`: команды и подписи вкладок.

### Этап F. Приёмка
- F1. `dotnet build` / `dotnet test` — все зелёные.
- F2. Кадры экрана (`SCRISELF_RENDER_DIR`) и сверка с макетом.
- F3. `docs/CHANGELOG.md`, `docs/HANDOFF.md`, ADR 012 (направление связи).

### Этап G. Полноразмерный холст и панели (задача 2)
- G1. Центральный холст занимает всю ширину между панелями; у «бумаги» убран `MaxWidth=780`.
- G2. Ширина левой и правой панелей меняется перетягиванием разделителей (`Thumb`),
  хранится в модели оболочки, пределы 200–560px.
- G3. Режим «Полный холст» вкл/выкл: боковые панели скрываются, холст занимает всю
  ширину с отступами по 20px; выключение возвращает панели и прежние ширины.
- G4. Тесты UI-дыма: переключение режима, зажим ширин, перетаскивание разделителя;
  новый кадр `03b-editor-full-canvas`.
