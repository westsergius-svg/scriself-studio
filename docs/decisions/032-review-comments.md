# ADR 032 — Правки и комментарии

Принято 2026-11-04. Второй этап редактуры, версия приложения 1.1.13.

Владелец данных — RichDocument.Review в Core. Комментарий хранит ID, автора,
дату UTC, текст, исходную цитату, диапазон UTF-16 и ID граничных абзацев.
Вставка у начала/конца не расширяет цитату, вставка внутри расширяет диапазон.
Полностью удалённый диапазон сохраняет комментарий с пометкой «Текст удалён»;
он не прикрепляется молча к соседним словам. Undo возвращает прежнюю привязку.

Правка хранит исходный документ без рекурсивной истории и заменённый диапазон
с оформлением. Отдельные непересекающиеся изменения можно принимать/отклонять
независимо. Соприкасающиеся изменения объединяются, включая продолжение ввода
и исправление ранее изменённого слова после выключения режима. Отклонение
возвращает исходные символы и стили; остальные диапазоны сдвигаются.
Служебный конечный токен позволяет учитывать оформление пустых абзацев.

ID абзацев проходят через адаптер и штатное клонирование AvaloniaRichEditor.
Разделение создаёт новый ID, склейка оставляет один; копирование не создаёт
дублирующих ID. Смещения пересчитываются по изменению текста, ID служат
дополнительной проверкой и навигацией, а не единственным якорем.

История видимого редактора остаётся единственным владельцем пользовательского
Undo/Redo. Расширение FlowDocument синхронизирует данные хоста перед снимком и
глубоко копирует их вместе с документом. Команды редактуры создают один штатный
шаг Undo. В ленте данные каждой сцены обрабатываются отдельно.

Данные входят в JSON документа, SQLite, ZIP, recovery и версии сцен. SQLite
получает схему 6, чтобы старая сборка не затёрла неизвестные ей данные.
Восстановление версии восстанавливает её комментарии и правки; страховочная
версия содержит текущие. Экспорт использует текущую чистую рукопись, без
комментариев, удалённых фрагментов и оформления служебных отметок.

Полные исходные снимки увеличивают размер книги. Их объём включён в бюджет
штатной истории Undo; автоматической очистки нерешённых правок нет. Хранение
только удалённых строк было отвергнуто: оно не восстанавливает оформление и
структуру абзацев. Привязка только к GUID абзаца не определяет диапазон после
разделения/склейки; поэтому ID дополнены преобразуемыми смещениями UTF-16.

LanguageTool и публикация в этот этап не входят.
