# ADR 025. Статистика использования и открытое скачивание

Дата: 2026-10-30
Статус: принято

## Контекст

Нужно видеть в админке число активных установок и скачиваний обновлений.
Существующий счётчик `downloads.download_count` учитывает только маршрут сайта,
а обновление приложения получает файл по прямой ссылке. Новое требование:
полностью отключить интеграцию VK и скачивать без входа и подписки.

## Решение

- Пересобранная версия 1.1.11 предлагает включить статистику. До согласия нет
  идентификатора и сетевых запросов статистики. Выбор доступен в настройках и
  не зависит от настройки проверки обновлений.
- `UsageStatisticsService` получает через существующие контракты настройки,
  часы и версию. Когда главное окно активно, отправляется POST на
  `https://scriself.com/app-activity.php`: только случайный UUID v4 профиля,
  версия и платформа. Номер сохраняется перед первым запросом. Не используются
  аппаратные идентификаторы, имя пользователя, аккаунты, проекты или рукописи.
- Успех — только HTTP 204. После него повторный сигнал в тот же день UTC
  подавляется; новая версия может отчитаться в тот же день. После ошибки —
  повтор не раньше 15 минут, без накопления истории. Запрос ограничен пятью
  секундами и отменяется при закрытии приложения. Параллельные вызовы объединяются.
- Сервер хранит SHA-256 случайного номера, время первого/последнего сигнала,
  последнюю версию и платформу. Уникальный ключ `(дата, установка)` исключает
  дубли за день. Активность за 7 и 30 дней считается по уникальным установкам.
  Публичный приёмник ограничивает размер, схему и частоту запросов.
- Скачивание выполняет общий потоковый обработчик. После открытия файла
  увеличивается `started`; после полной выдачи — `completed`. HEAD, ошибки
  доступа и отсутствующие файлы не считаются. Range получает целый файл с
  HTTP 200, без отдельного учёта частей. Сбой статистики не прерывает передачу.
- Источники: `website`, `updater`, `direct`. Для прямого канала приложение
  определяется по существующему User-Agent, без привязки к установке.
  Имена файлов и источники дают разбивку по выпускам; повторное скачивание
  увеличивает счётчик. Источник не является доказательством личности.
- Apache перенаправляет прежние ссылки установщиков в `update-download.php`.
  Он выдаёт только текущие файлы из манифестов Windows/macOS. Остальные публичные
  сборки доступны через `/download/file/{id}`; `is_public=0` остаются скрытыми.
  Прямой доступ к произвольным файлам и PHP в uploads закрыт.
- VK больше не вызывается. Удалены проверка членства, кнопки входа, ссылки
  сообщества и кнопка распространения через VK. Старые маршруты входа ведут на
  `/download`, старые модуль и настройки заменяются неактивными файлами.
  Вход администратора сайта сохраняется.
- Админка показывает активность за 1/7/30 дней, отсутствие сигналов за 30 дней,
  версии, дневной график, скачивания за 30 дней и за всё время. Данные доступны
  только через существующую авторизацию администратора.

## Последствия

Это статистика установок с включённой отправкой, а не список людей и не измерение
времени письма. Отсутствие сигнала не доказывает неиспользование: возможны офлайн
или отключённая статистика. Полная выдача файла не подтверждает его установку.
Ранее произошедшие запуски и прямые скачивания не восстанавливаются; прежний
счётчик сайта сохраняется отдельно. Публичный приёмник нельзя использовать для
биллинга или лицензирования.

Поставка состоит из обновления приложения и накладываемых файлов сайта.
Личные настройки, проекты и конфигурация базы сайта в комплект не включаются.
По явному требованию номер остаётся 1.1.11: уже установленная старая 1.1.11
не обнаружит замену файла как новую версию, её нужно обновить вручную.

## Проверка

Тесты клиента проверяют согласие, сохранение номера, повторы, смену версии,
границы UTC, отмену и недоступность сети/диска. Тесты PHP используют одноразовую
MariaDB и HTTP-сервер: уникальность, транзакции, периоды, доступ без аккаунта,
отключение старого входа, HEAD/Range, прерванную передачу, ошибки базы и доступ
к админке. Правила `.htaccess` требуют отдельной проверки на Apache хостинга.
