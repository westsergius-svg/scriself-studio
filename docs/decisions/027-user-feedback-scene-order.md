# ADR 027 — Порядок шагов сцены и повторяющиеся названия глав

Решение: принято в рамках исправлений обратной связи 2026-11-04.
Координация изменения Contracts — текущая задача архитектора приложения.

## Проблема
Автору нужен независимый порядок шагов в сцене, перестановка линий проекта
и повторяющиеся названия глав с точкой зрения одного персонажа.

## Контракт и совместимость
- `MoveEntityAsync` поддерживает существующий `EntityKind.PlotLine`.
  Порядок считается среди неудалённых элементов. Сигнатура не меняется.
- Создание и переименование главы проверяют непустое название и длину,
  но разрешают совпадения. Идентичность и адресация остаются по Guid.
- `SceneMetadata.PlotLineStepOrder` — необязательный JSON-массив идентификаторов.
  Старые файлы читаются с пустым массивом, схема контейнера не меняется.
  В старом ZIP-формате порядок хранится в необязательном `scriselfStepOrder`
  сцены, а `scriselfId` сохраняет Guid, на который ссылаются этапы линий.
- `SceneDto.PlotLineStepOrder` передаёт копию предпочтительного порядка.
  `UpdateSceneRequest.PlotLineStepIds` сохраняет порядок переданного списка,
  удаляет дубликаты; null по-прежнему означает «не менять».
- Источником связей остаются `PlotLineStep.SceneIds`. Удалённые или отвязанные
  шаги из сохранённого порядка игнорируются; новые следуют за известными.
  Перемещение в сцене не меняет порядок линии и другие сцены.

Проверки: одинаковые заголовки с разными Guid, перестановка рядом с удалёнными
элементами, сохранение/повторное открытие локального порядка, старые файлы.
