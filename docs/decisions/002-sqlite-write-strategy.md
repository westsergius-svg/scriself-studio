# ADR 002. Сохранение проекта: полный снимок через временный файл

Дата: 2026-09-27
Статус: принято

## Контекст

ТЗ п. 13 требует атомарной записи через временный файл и резервную копию перед заменой.
ТЗ п. 23 требует выбрать одну согласованную стратегию для SQLite: транзакции в открытой
базе **либо** снимок через временный файл. Там же запрещено подменять открытую базу при
активном WAL.

## Решение

Выбран полный снимок:

1. Запись новой базы целиком во **временный** файл рядом с целевым.
2. `CREATE TABLE`/миграции выполняются в этом временном файле.
3. При включённых резервных копиях существующий файл копируется в `.bak`.
4. Временный файл атомарно заменяет целевой через `File.Replace`.
5. Режим журнала — `journal_mode = DELETE`, пул соединений выключен (`Pooling = false`).
   WAL не используется.

Перед записью создаётся снимок восстановления; он удаляется только после успешной замены
(см. ADR 005).

## Последствия

- Открытая база никогда не подменяется «на месте», WAL не участвует в замене.
- При ошибке целевой файл остаётся нетронутым.
- Стоимость — полная перезапись файла на каждое сохранение; для рукописи это приемлемо,
  а корректность важнее скорости.
- Признак несохранённых изменений снимается только после успешной замены.

## Альтернативы

Долгоживущее соединение с транзакциями `INSERT`/`UPDATE` — отклонено: сложнее обеспечить
«старый файл не повреждён при сбое» и совместимость с требованием резервной копии.
