# ADR 022. WYSIWYG rich-text editor for scenes

Дата: 2026-10-12
Статус: принято (частично заменяет редакторскую часть ADR 020)

## Контекст

После ADR 020 заказчик уточнил требование: форматирование текста должно быть видно
не только после сохранения, но и непосредственно в редакторе. Нужны символьные стили,
абзацное выравнивание и списки с сохранением при повторном открытии.

AvaloniaEdit принудительно отображает абзацы с выравниванием по левому краю, поэтому
не обеспечивает требуемое WYSIWYG-поведение для уже поддерживаемой моделью документа
разметки. `AvaloniaRichEditor` поддерживает нужные возможности, но требует .NET 10 и
Avalonia 12.

## Решение

1. Использовать `AvaloniaRichEditor` как интерактивный редактор сцены; преобразовывать
   его документ в каноническую модель `RichDocument` перед передачей в `EditorEngine`.
2. Хранить символьное форматирование, выравнивание, тип блока, уровень списка и стиль
   маркера в модели проекта. Сохранять эту модель обычным механизмом проекта и
   восстанавливать её в rich-text контроле при открытии сцены.
3. Показывать открытую главу как один непрерывный `FlowDocument`. Сцены объединяются
   только для отображения разделителями `DividerBlock`; при вводе документ разделяется
   обратно и сохраняется в модель каждой сцены отдельно. Разделитель следует за текстом,
   без фиксированной высоты сцены; нижний отступ сохраняет прежний минимальный размер
   пустой сцены. Заголовок над лентой показывает название сцены под курсором.
   В начало каждой сцены вставляется видимый заголовок с номером, названием, статусом
   и объёмом. Это элемент отображения: при обратном преобразовании он отбрасывается и
   не попадает в текст сцены. Над листом показывается кликабельная лента плашек всех
   сцен главы — она сохраняет компоновку ADR 020.
4. Зафиксировать .NET 10 и Avalonia 12 как целевые версии приложения для совместимости
   с компонентом.
5. Сохранить из ADR 020 компоновку ленты сцен и редактируемую панель контекста сцены;
   заменить только решение о штатном `TextBox` и отказе от движка/форматирования.
6. В дереве книги кнопка добавления сцены показывается рядом с главой при наведении;
   команда создаёт сцену именно в этой главе.

## Последствия

- Выравнивание, списки, заголовки, цитаты и символьное форматирование отображаются
  непосредственно при редактировании.
- Адаптер между `FlowDocument` компонента и `RichDocument` приложения отвечает за
  явное преобразование поддерживаемых видов блоков и inline-стилей.
- UI smoke tests используют xUnit v3, необходимый для обнаружения тестов
  `AvaloniaFact` из Avalonia 12.
- Для сборки и запуска требуется установленный .NET 10 SDK.

## Альтернативы

1. **Оставить AvaloniaEdit и имитировать выравнивание рендерером.** Отклонено: контроль
   принудительно задаёт выравнивание абзаца, поэтому поведение не соответствует модели
   документа и недостоверно при редактировании.
2. **Сохранить `TextBox` и форматировать только при экспорте.** Отклонено: заказчик
   требует WYSIWYG непосредственно во время ввода.
