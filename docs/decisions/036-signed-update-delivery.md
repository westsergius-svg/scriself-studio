# ADR 036. Подписанный выпуск и потоковая загрузка обновления

Дата: 2026-11-17
Статус: принято

## Контекст

Прежний updater запускал полученный файл без проверки SHA-256. Хеш, переданный тем
же каналом без подписи, не удостоверяет автора выпуска. Буферизация установщика
около 304 МБ и общий срок 25 секунд также мешали загрузке по медленному соединению.

## Решение

1. Публичный RSA-ключ закреплён в `SignedUpdateManifest` в Core. Манифест содержит
   SHA-256 и Base64-подпись RSA-PSS/SHA-256 канонического UTF-8 payload версии 1:
   префикс протокола, нормализованная версия, имя файла, хеш в нижнем регистре и
   Base64 от заметок. Формат полностью описан в [контрактах](../CONTRACTS.md).
2. Подпись проверяется при чтении манифеста и перед загрузкой. Повреждённый манифест
   или подпись прекращают проверку; переход к неподписанному резервному листингу
   запрещён. Старый манифест без подписи, даже с SHA-256, предлагает официальную
   страницу ручного скачивания.
3. Адрес файла должен точно соответствовать HTTPS-каталогу канала и безопасному имени
   установщика нужной платформы. Автоматические перенаправления HTTP выключены.
4. `ResponseHeadersRead`, потоковая запись и хеширование ограничивают расход памяти.
   Сроки разделены: 25 секунд на запрос/метаданные, 2 часа на загрузку и 60 секунд
   бездействия. Размеры ограничены 1 МиБ для метаданных и 2 ГиБ для файла. Каждая
   загрузка получает отдельную папку; ошибка/отмена удаляют частичный файл.
5. Сервис запоминает только полностью проверенные загрузки. Перед запуском повторно
   хеширует файл под блокировкой чтения. На Windows во время решения о запуске нельзя
   записать или удалить этот файл. `Process.Start` должен вернуть процесс; только
   после этого вызывается завершение приложения. Отказ сохраняет возможность повтора.
6. `LauncherViewModel` сохраняет рабочее пространство перед запуском и показывает
   ошибку отказа запуска, сохраняя книгу открытой. Core не зависит от App или UI.
7. Windows-builder вызывает `write-update-manifest.ps1`. Mac-builder вызывает отдельный
   .NET-инструмент, использующий тот же `SignedUpdateManifest.Payload/Verify`, что
   приложение. Ключ задаётся локальным путём, хранится вне исходников и не попадает
   в манифест. Подпись проверяется до атомарной замены манифеста. Без ключа генераторы
   сохраняют путь ручной подготовки/скачивания; автоматическая установка требует подписи.

## Последствия

Подмена файла или метаданных без закрытого ключа не разрешает автоматический запуск.
Подпись не является Windows Authenticode или нотариальной подписью приложения Mac.
Смена ключа и более новый протокол требуют отдельного совместимого перехода. Запуск
`open` на Mac проверяет принятие команды ОС, а установка приложения остаётся ручной.

Реальный выпуск, установка поверх пользовательской версии и живой запуск macOS не
входили в эту проверку. Синтетические подписанные файлы не исполнялись.

## Проверки

`UpdateIntegrityTests` проверяет закреплённый ключ на выходе обоих генераторов,
подмену файла/метаданных, неподписанный выпуск, медленный/зависший поток, отмену,
ограничения размера, отдельные папки, повтор после отказа запуска и удержание файла
Windows. `WorkspaceSaveTests` проверяет сохранение книги и сообщение при отказе.
Результаты и материалы — [журнал аудита](../WORKLOG_AUDIT_FIXES.md).
