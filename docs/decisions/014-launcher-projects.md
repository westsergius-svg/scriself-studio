# ADR 014. Лаунчер «Мои проекты»: три колонки и сводка в списке последних

Дата: 2026-10-02
Статус: принято

## Контекст

Стартовый экран приложения (лаунчер) должен был соответствовать макету
«Мои проекты»: слева навигация по разделам, в центре список проектов с поиском и
созданием, справа — контекст выбранного проекта. Прежний лаунчер был одной
колонкой со списком путей и не показывал ни сводку проекта, ни его контекст.

Список последних проектов хранится в настройках приложения
(`AppPreferences.RecentProjects`) и раньше содержал только путь, имя и дату
открытия. Чтобы карточка выглядела как в макете, ей нужны описание и счётчики
(книги, главы, сцены, персонажи, сюжетные линии) — но читать каждый файл проекта
при отрисовке списка нельзя.

## Решение

### Раскладка

`LauncherView` — сетка `228,*,336`: левая навигация (разделы, «Мои проекты» со
счётчиком), центральная панель «Мои проекты» (поиск, «Открыть проект»,
«Новый проект» и список карточек) и правая панель «Контекст проекта» (имя,
сводка, описание, статистика, действия, цитата). Разделы «Шаблоны», «Облако» и
«Блог» пока не реализованы и честно сообщают об этом через `ShowComingSoonCommand`.

### Сводка в списке последних

`RecentProjectEntry` дополнен кэшируемыми полями: `Description`, `BookCount`,
`ChapterCount`, `SceneCount`, `CharacterCount`, `PlotLineCount`, `UpdatedAt`.
Поля пишутся при открытии/сохранении проекта (`RememberProjectAsync`) и
необязательны в JSON, поэтому старые файлы настроек читаются без миграции.
Карточка показывает «N книга · N глав · N сцен» и дату изменения.

Для **открытого** проекта карточка берёт живые счётчики из `IProjectService.Current`
(`MergeWithOpenProject`), а не из кэша: автор добавляет главы и сцены, и карточка
обновляется сразу.

### События

`LauncherViewModel` сам подписан на `ProjectOpened`, `ProjectClosed` и
`ProjectChanged` и обновляет своё состояние. `ShellViewModel` больше не вызывает
`SyncProjectState` лаунчера на каждое событие сцены: иначе автосохранение
перестраивало бы список проектов каждые пять секунд. `ProjectService.Mutate`
публикует `ProjectChanged` при любой правке структуры, а не только при смене
флага «грязный».

## Последствия

- Лаунчер соответствует макету и работает без чтения файлов проектов при старте.
- Кэш сводки обновляется при открытии и сохранении; старые записи без счётчиков
  показывают только имя и дату, пока проект не открыт заново.
- «Убрать из списка» удаляет запись из последних, но **не удаляет файл проекта** —
  необратимое удаление файла остаётся отдельным осознанным действием.
- Список последних проектов теперь действительно переживает перезапуск:
  `AppPreferences.RecentProjects` получил сеттер, иначе генератор System.Text.Json
  не заполнял коллекцию только для чтения при загрузке настроек.
- Разделы «Шаблоны», «Облако», «Блог» и «Экспорт» — заглушки (сообщение о будущей
  версии), а не молчащие кнопки.

## Альтернативы

1. Читать файлы проектов при отрисовке списка, чтобы всегда иметь точную сводку.
   Отклонено: старт приложения замедлялся бы пропорционально числу последних
   проектов, а часть файлов может быть недоступна.
2. Хранить сводку только в памяти сессии. Отклонено: карточки теряли бы сводку
   после перезапуска, ради которого лаунчер и нужен.
3. Удалять файл проекта кнопкой «Удалить проект» из макета. Отклонено: удаление
   необратимо и не подтверждается; безопаснее убирать запись из списка.
