# ADR 005. Снимок восстановления — JSON рядом с проектом

Дата: 2026-09-27
Статус: принято

## Контекст

ТЗ п. 13 и 28 требуют хранить recovery отдельно и удалять его только после успешного
сохранения. ТЗ п. 28 описывает сценарий: аварийное закрытие → при следующем запуске
сообщение о восстановлении → открыть / сохранить как / удалить.

## Решение

- Снимок восстановления — файл `<project>.scri.recovery` рядом с проектом.
- Формат — JSON канонической модели проекта (`CoreJsonContext`), а не SQLite: снимок
  нужен для быстрой записи перед сохранением и не обязан совпадать со схемой файла.
- Снимок создаётся **до** записи проекта и удаляется **после** успешной замены файла.
- Обнаружение — `IProjectService.DetectRecoveryAsync`; дальнейшие действия —
  `RecoverAsync` (открыть восстановленный проект) и `DiscardRecoveryAsync` (удалить).

## Последствия

- Если приложение упадёт во время сохранения, состояние не потеряется: снимок остаётся на
  диске и обнаруживается при следующем открытии.
- Ошибка записи снимка не блокирует сохранение, но фиксируется в логе
  (`SaveCoreAsync` продолжает работу, а снимок — вспомогательный).
- Снимок содержит полный текст сцены, поэтому он, как и сам проект, остаётся локальным;
  полный текст рукописи не пишется в логи (ТЗ п. 19).
