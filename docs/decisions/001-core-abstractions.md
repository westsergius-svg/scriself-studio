# ADR 001. Абстракции ядра остаются в `Core`

Дата: 2026-09-27
Статус: принято

## Контекст

ТЗ п. 33 требует: «Contracts, Core и EditorEngine не зависят от Avalonia». ТЗ п. 7
говорит, что все публичные интерфейсы находятся в `ScriSelfStudio.Contracts`.

Ядру нужны шина событий (`IEventBus`) и источник времени (`ISystemClock`). Если поместить
их в `Contracts`, то ядро, которое их использует, обязано ссылаться на `Contracts`,
а `Contracts` — на `Core` (там модель и события). Получается цикл.

## Решение

Абстракции, которые **реализует ядро**, объявлены в `Core`:

- `Core/Events/IEventBus.cs`, `Core/Events/EventBus.cs`;
- `Core/ISystemClock.cs`, `Core/SystemClock.cs`.

Записи событий приложения живут в `Contracts/Events/AppEvents.cs` и используют модель ядра.
`Contracts` ссылается только на `Core`.

## Последствия

- `Core` не имеет ни одной ссылки на проект или пакет — самое строгое правило сохраняется.
- Единственная разрешённая ссылка — `Contracts → Core`.
- Для UI-модулей и сервисов тип `IEventBus` виден через `Core`, тип события — через
  `Contracts`; это не создаёт цикла.

## Альтернативы

Отдельный проект `Abstractions` между `Core` и `Contracts` — отклонён: лишний проект ради
двух интерфейсов и новая стрелка зависимостей.
