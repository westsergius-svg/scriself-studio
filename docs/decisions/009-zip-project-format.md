# ADR 009. Старый ZIP-формат как полноценный формат проекта

Дата: 2026-09-27
Статус: принято

## Контекст

В `C:\Users\Papa\Documents\Scriborium` накопились проекты четырёх форматов:

| Формат | Файлы |
| --- | --- |
| Наш текущий (SQLite `schema_info/project/…`) | `3.scri` |
| ZIP-контейнер (`manifest.json` + `content.json`) | `2.scri`, `курс.scri` |
| Модульный SQLite, `formatVersion = 2` | `Первый раз.scri`, `1 (2).scri`, `1 (3).scri` |
| Модульный SQLite, `appVersion = scri.p 0.1.1` | `1.scri` |
| Модульный SQLite, `appVersion = ScriSelf Studio beta 0.1` | `It's my best book…scri` — по решению владельца не поддерживаем |

Наш редактор открывал только файлы своего формата: на остальных он сообщал «файл повреждён»,
хотя внутри реальные рукописи. Требование владельца: **все версии должны открываться,
а ZIP-проекты должны и сохраняться в исходном формате**, чтобы файл продолжали открывать
старые приложения.

## Решение

1. **ZIP — не «импорт», а полноценный формат.** Проект, открытый из ZIP, при сохранении
   записывается обратно в ZIP с теми же именами и структурой (`manifest.json`,
   `content.json`). Старые приложения продолжают открывать файл.
2. **Формат определяется по содержимому файла**, а не по расширению: сигнатура `PK` —
   ZIP-контейнер, `SQLite format 3` — наш SQLite. Выбор хранилища выполняет
   `RoutingProjectStore`; `ProjectService` о формате не знает.
3. **Переносятся** книга, главы, сцены, тексты, статусы сцен, описания-замысел
   (цель/конфликт/результат → описание сцены) и сюжетные линии из `timeline.plotlines`
   с привязкой к сценам.
4. **Поля, которых у нас нет, не выбрасываются.** Исходный `content.json` целиком хранится
   в модели (`Project.SourceDocumentJson`) и при записи служит основой: мы заменяем только
   те поля, которые редактируем. Так сохраняются автор, жанр, предисловие, персонажи,
   локации, объекты, тома и служебные поля глав (`chapterTextHtml`, `volumeId` и прочие).
5. **Связь сущностей с исходными идентификаторами** хранится в `ProjectEntity.SourceId`
   (`chapter_001`, `scene_001`): при сохранении узел берёт свой исходный id и свои поля,
   поэтому порядок и служебные данные не «переезжают» на соседей. Новые сущности получают
   сгенерированные id вида `chapter_002`.
5. **Безопасность записи.** Открытие файла никогда его не изменяет. Первое сохранение
   проекта в «чужом» формате **всегда** создаёт `<файл>.scri.bak` с полной предыдущей
   версией, даже если резервные копии в настройках выключены (ТЗ п. 13).
6. **Ранние модульные форматы** (SQLite с таблицами `entities`/`meta`) импортируются
   в текущую модель (`LegacyModularImporter`). Формат определяется по наличию таблиц
   `entities` и `meta`, а не по `appVersion`, поэтому подходят все известные сборки.
   Переносятся книга, главы, сцены, тексты, персонажи, сюжетные линии и их этапы.
   Что перенести точно нельзя, попадает в `ProjectLoadResult.Warnings` и показывается
   пользователю в строке состояния через событие `ProjectImported`.

## Последствия

- Проекты `2.scri` и `курс.scri` открываются, редактируются и сохраняются с сохранением
  совместимости: проверено на копиях реальных файлов, оригиналы не изменялись.
- Наш формат остаётся основным для новых проектов; ZIP поддерживается как дополнительный.
- Хранение исходного документа увеличивает размер проекта в памяти, но не влияет на файл,
  пока проект остаётся в ZIP-формате.
- Правка описания сцены в нашем UI не переписывает старые поля `goal/conflict/result`:
  они сохраняются как были. Это осознанное ограничение, а не потеря данных.
- При импорте раннего модульного файла его SQLite-соединение открывается без пула:
  иначе файл остался бы заблокированным и первое сохранение не смогло бы подменить
  его атомарно. То же требование действует для тестовых фикстур.

## Альтернативы

- **Конвертировать ZIP в наш SQLite при открытии.** Отклонено: владелец требует, чтобы файл
  продолжал открываться в старых приложениях, значит формат надо сохранять.
- **Записывать ZIP только «по кнопке» (экспорт).** Отклонено: пользователь должен просто
  нажать «Сохранить», не выбирая формат.
- **Определять формат по расширению.** Отклонено: расширение у всех версий одинаковое
  (`.scri`), а содержимое — разное.
- **Терять неизвестные поля.** Отклонено: молчаливая потеря авторских данных недопустима
  (ТЗ п. 12, 43).
