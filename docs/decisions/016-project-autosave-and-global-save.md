# ADR 016. Автосохранение всего проекта, глобальный Ctrl+S и сохранение новой линии

Дата: 2026-10-03
Статус: принято

Уточнение 2026-11-17: ADR 035 добавляет очередь операций ProjectService и общий
IWorkspaceSaveService для всех черновиков. Прежнее ограничение «нет блокировки»
и делегирование глобального сохранения только редактору ниже описывают исходный этап.

## Контекст

Оболочка показывает «Автосохранение: включено», а интервал и выключатель есть в настройках
проекта (ТЗ п. 11). По факту таймер был только у редактора сцены: он сохранял проект,
когда в тексте были несохранённые правки. Правки на других экранах — сюжетные линии,
карта книги, персонажи — оставались в снимке в памяти и на диск не попадали: кнопки
сохранения вне редактора не было, а `Ctrl+S` был привязан только в `EditorView`.

Отдельный дефект экрана линий: сохранение по потере фокуса требовало выбранной линии,
а новая линия до первого сохранения нигде не выделена — создать линию из UI было нельзя.

## Решение

1. **Автосохранение проекта в оболочке.** `ShellViewModel` заводит `DispatcherTimer`
   с проверкой раз в 5 секунд (ТЗ п. 11). Снимок пишется, когда проект открыт,
   `ProjectSettings.AutoSaveEnabled` включён, `IProjectService.IsDirty` истинно и прошёл
   интервал `AutoSaveIntervalSeconds` с последней правки. Момент последней правки
   обновляется на `ProjectChanged`, поэтому запись идёт после паузы, а не в каждом
   изменении.
2. **Совместимость с автосохранением редактора.** Пока в сессии редактора есть
   несохранённый текст (`EditorViewModel.IsDirty`), оболочка молчит: автосохранение
   редактора фиксирует текст и сохраняет проект целиком. Так две записи не гоняют файл
   одновременно (в `ProjectService` нет блокировки на запись).
3. **Глобальное сохранение.** `ShellViewModel.SaveCommand` доступна при открытом проекте
   (`CanExecute`), привязана к кнопке в верхней строке и к `KeyBinding Ctrl+S` уровня окна,
   поэтому работает на любом экране. Если открыта сцена, команда делегирует сохранение
   редактору (он доносит текст до проекта), иначе пишет проект напрямую.
4. **Сохранение новой линии.** `TimelineViewModel.CommitLineAsync` (потеря фокуса поля)
   проверяет готовность черновика (`CanPersist`), а не выбранную линию: новую линию можно
   сохранить, пока она ещё не выделена. На экране линий появилась кнопка
   «Сохранить линию» (`SaveLineCommand`) — явный путь для только что созданной линии.

## Последствия

- Правки структуры, линий и персонажей доходят до файла без ручного вмешательства —
  поведение совпадает с надписью «Автосохранение: включено».
- `Ctrl+S` и кнопка в шапке сохраняют проект с любого экрана, а не только из редактора.
- Новую сюжетную линию можно создать и сохранить: по потере фокуса или кнопкой.
- Запись не конкурирует с автосохранением редактора, но при этом зависит от того, что
  редактор рано или поздно сохранит свой текст (его таймер это делает).

## Альтернативы

1. **Только кнопка «Сохранить» без автосохранения.** Отклонено: противоречит настройке
   и надписи «Автосохранение: включено», которые уже есть в интерфейсе.
2. **Кнопка сохранения на каждом экране отдельно.** Отклонено: дублирует команду и
   расходится с единым `Ctrl+S`; общая команда оболочки проще и предсказуемее.
3. **Сохранять при закрытии без диалога.** Отклонено: молчаливая запись в чужой файл
   без спроса нежелательна. Диалог несохранённых изменений (ТЗ п. 14) — отдельная задача:
   текущий `ConfirmAsync` умеет только два ответа, нужен третий («Отмена»).
4. **Блокировка записи в `ProjectService`.** Отклонено в этой задаче: достаточно того,
   что оболочка уступает редактору; общий шлюз — более крупное изменение хранения.
