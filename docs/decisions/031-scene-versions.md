# ADR 031 — Версии сцен

Принято 2026-11-04, первый этап разрешённого пользователем развития редактуры.
Версия приложения не меняется (1.1.13).

## Контракт и хранение

SceneVersion хранит ID, название, дату UTC, ревизию источника, признак страховочного
снимка и полную копию RichDocument. Владелец — Scene.Versions, операции —
IProjectService. Список выдаёт только сведения; документ версии читается отдельной
копией. Мутации синхронны и помечают проект изменённым; UI сохраняет его и сообщает
отдельно об ошибке записи. При ошибке изменения остаются в памяти для повторной записи.

SQLite: схема 5, отдельная таблица scene_version. Миграция создаёт таблицу в копии;
предыдущий файл сохраняется в .bak. Старый ZIP: sceneVersions в разделе scriself,
ключ — тот же DocumentKey, что у форматированного текста. Recovery включает историю
через единую CoreJson-сериализацию. Повреждённая история не заменяется молча пустой.

## Поведение

Перед историей редактор фиксирует и сохраняет все сцены ленты. Модальное окно
исключает одновременный ввод в книгу. Снимок содержит полный текст с оформлением;
восстановление сначала добавляет страховочный вариант, затем заменяет текущий документ,
увеличивает ревизию и публикует SceneChanged. После окна движок перечитывает сцену,
чтобы не вернуть старый документ последующим автосохранением.
Обычный просмотр не сбрасывает Undo. После восстановления история ввода обоих
редакторов начинается заново; предыдущий текст возвращается из страховочной версии.
У компонента AvaloniaRichEditor метод LoadDocument открыт для хоста, чтобы при загрузке
готового документа использовать штатный сброс Undo, выделения и позиции курсора.

Сравнение текста ограничивает объём матрицы различий; большие изменения показываются
целыми фрагментами. Оформление проверяется отдельно и видно в двух просмотрах.
Никакого автоматического удаления старых версий и фоновой записи каждой клавиши.

## Последствия и границы

Файл книги растёт с каждым сохранённым вариантом. Старые сборки не читают SQLite
схемы 5; перед миграцией остаётся резервная копия. Сторонние старые ZIP-приложения
могут не сохранить расширение истории при пересохранении. История не входит в экспорт.
Режим правок, комментарии и грамматика — следующие отдельные этапы.
