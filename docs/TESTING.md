Актуальная сборка исправлений — ветка `codex/audit-fixes`, .NET 10, Avalonia 12.1.4,
схема SQLite 6. Результаты общего Release и живого запуска фиксируются в
[WORKLOG_AUDIT_FIXES.md](WORKLOG_AUDIT_FIXES.md); разделы выпусков ниже — исторические.
Число тестов старого выпуска не подтверждает текущее состояние.

| Набор | Проверяемое поведение |
| --- | --- |
| `SaveIntegrityTests` | Ревизия/снимок, правка во время записи, очередь операций, recovery, два владельца и внешний конфликт, повреждённый JSON |
| `ZipIntegrityTests` | Разные тексты/оформление/версии при нескольких главах/книгах, старые карты, одинаковые ID, безопасный отказ неоднозначному архиву |
| `WorkspaceSaveTests` | Фиксация всех панелей, выход/смена/обновление, отказ записи, новая правка, отказ запуска установщика |
| `UpdateIntegrityTests`, `UpdateFeedTests` | Подпись Windows/Mac, хеш, удержание файла, отсутствие резервного обхода подписи, медленный поток/отмена/размер, повтор запуска |
| `PdfExportTests` | Реальные PDF: начертания/линии, списки, длинные слова, переносы страниц, выравнивание, оглавление/карточки |
| `CompactExportTests` | 800×480 во всех пяти темах, выбор Markdown мышью/клавиатурой, предпросмотр и экспорт, возврат к 1440×900 |
| `MapVirtualizationTests` | 500 сцен в одной/25 главах, ограниченное число контейнеров, прокрутка, выделение после переработки контейнера и открытие |

Опциональные материалы создаются через `SCRISELF_AUDIT_PDF_OUTPUT_DIR` и
`SCRISELF_AUDIT_UI_OUTPUT_DIR`. PDF дополнительно разобраны pypdf и отрисованы
Poppler; снимки/извлечённые тексты и измерения контраста находятся в
`artifacts/audit-fixes`. Headless-замеры карты не следует выдавать за native GPU/FPS.

Для Debug-проверки в отдельном профиле задаётся `SCRISELF_DEBUG_DATA_ROOT`; Release
не использует эту переменную. Диагностика живого приложения работает только в Debug;
после проверки приложение нужно закрыть. macOS manifest проверяется реальным Core,
но сборка/запуск macOS и настоящий установщик в эту проверку не входят.

Требования: ТЗ п. 15, 43, 58, 59.

## Как запускать

```powershell
dotnet restore
dotnet build --configuration Release
dotnet test --configuration Release
```

Один проект за раз (MSBuild не принимает несколько путей `.csproj` одновременно):

```powershell
dotnet test tests\ScriSelfStudio.Core.Tests\ScriSelfStudio.Core.Tests.csproj
dotnet test tests\ScriSelfStudio.EditorEngine.Tests\ScriSelfStudio.EditorEngine.Tests.csproj
dotnet test tests\ScriSelfStudio.Persistence.Tests\ScriSelfStudio.Persistence.Tests.csproj
dotnet test tests\ScriSelfStudio.BookArchitecture.Tests\ScriSelfStudio.BookArchitecture.Tests.csproj
dotnet test tests\ScriSelfStudio.IntegrationTests\ScriSelfStudio.IntegrationTests.csproj
dotnet test tests\ScriSelfStudio.UiSmokeTests\ScriSelfStudio.UiSmokeTests.csproj
```

Тестовый фреймворк один на всю solution — xUnit (ТЗ п. 32).

Для серверных счётчиков и скачивания сайта есть отдельный сценарий
`website/tests/statistics_test.php`: он создаёт одноразовую базу MySQL/MariaDB и
локальный HTTP-стенд, не использует настройки рабочего сайта. Требования, запуск
с PHP 8.2 и `pdo_mysql` описаны в [инструкции сайта](../website/README.md).
Сценарии проверяют доступ без VK, учёт активности/скачиваний, ошибки, доступ к
админке и замену файла выпуска без потери счётчика. Правила Apache `.htaccess`
проверяются отдельно на хостинге, поскольку встроенный PHP-сервер их не выполняет.

## Что именно проверяется

### Правила зависимостей

`ArchitectureRulesTests` загружает сборки и проверяет, что:

- доменные сборки не ссылаются на `Avalonia`;
- UI-модули не ссылаются на `ScriSelfStudio.Persistence`;
- только `ScriSelfStudio` (App) регистрирует реализации.

### Обязательный пользовательский путь (ТЗ п. 31)

`UserPathTests` проходит сценарий: создать проект → книгу → главу → сцену → ввести текст →
сохранить → закрыть → открыть → проверить текст. Отдельно проверяется, что закрытие без
сохранения не меняет файл на диске.

### Сессия редактора

`SceneEditorEngineTests` проверяет поведение, а не реализацию: вставку и удаление текста,
наследование форматирования, разделение и слияние блоков, отмену и повтор, переключение
форматирования, стиль блоков, поиск, статистику, commit и конфликт ревизий, кириллицу,
emoji и составные символы.

### UI

Headless-тесты (`Avalonia.Headless.XUnit`) открывают реальное окно через
`AvaloniaTestApplication`, показывают экран и проверяют, что у каждой кнопки есть команда
(ТЗ п. 15: UI не содержит фиктивных кнопок). Команды выполняются на настоящих сервисах
с подменёнными диалогами.

`InterfacePolishTests` проверяет перетаскивание границ рабочих панелей в обе
стороны при ширине окна 800/1152/1600, видимость крестиков и удаление этапов,
раскрытие описаний карты после сохранения, независимый выбор навигации и
упрощённый китайский. Проверки языка включают сохранение пользовательских текстов
и параметров экспорта, а перезапуск начинается с русского языка, чтобы проверить
чтение настройки с диска. `SettingsViewTests` проверяет восстановление всех четырёх
тем с нужной компоновкой. `ScreenRenderTests` снимает все экраны каждой темы;
для сохранения кадров задаётся переменная `SCRISELF_RENDER_DIR`.

`CharactersAndPlotLinesTests.New_arc_stage_descriptions_survive_first_save_and_project_reopen`
проверяет описание нового этапа после первого сохранения и повторного открытия файла.

### Карта книги (ТЗ п. 27)

- `BookMapLayoutTests` (BookArchitecture) — чистая геометрия: ширина столбца от числа глав,
  пределы `48…200`, центрирование остатка, флаг «не влезает», независимость позиций от выбора
  и ширина активной главы.
- `BookMapTests` (IntegrationTests) — карта из сервисов: столбец на главу, порядок и номера,
  раскрытие активной главы без сдвига соседей, единое выделение с деревом, объём сцены и
  главы в словах, отметка «ключевая» и её сохранность после переоткрытия проекта.
- `ArchitectureMapViewTests` (UiSmokeTests) — карта действительно строится в окне:
  столбцы отрисованы и видимы, переключение на «Список» показывает дерево.

### Форматы файла проекта (ТЗ п. 5, 13)

- `LegacyZipProjectTests` (IntegrationTests) — три проверки старого ZIP-формата:
  открытие со структурой, текстами и сюжетными линиями; сохранение в тот же формат с
  резервной копией и сохранением полей, которых нет в нашей модели (автор, персонажи,
  тома, служебные поля глав); переоткрытие после правки текста.
- Формат определяется по сигнатуре: `ScriZipFormat.HasZipSignature` и `RoutingProjectStore`.

### Персонажи и сюжетные линии (ТЗ п. 27, 35; ADR 010)

- `CharactersAndPlotLinesTests` (BookArchitecture) — шесть проверок модели: новый персонаж
  получает семь канонических шагов арки; поля карточки сохраняются; имена персонажей
  уникальны; этап линии ссылается на персонажа и конкретный шаг его арки; участник этапа
  обязан быть существующим персонажем; удаление персонажа убирает его из этапов.
- `SchemaMigrationTests` (IntegrationTests) — миграция схемы 1 → 2: файл версии 1
  открывается, структура и текст сцены остаются, таблицы персонажей создаются, резервная
  копия `<файл>.scri.bak` появляется, после сохранения персонаж читается при повторном
  открытии, версия схемы становится текущей.

### Возможности и пределы MCP-диагностики (ADR 006)

Сервер `AvaloniaMcp` 0.4.0 читает состояние UI полностью, но управляет им ограниченно:

| Операция | Поддержка |
| --- | --- |
| Окна, визуальное и логическое дерево, свойства, стили, ресурсы, `DataContext`, ошибки биндинга, снимок | Да |
| Нажатие кнопки с привязанной `ICommand` | Да |
| `input_text` в `TextBox` | Да |
| `set_property` (скалярные свойства) | Да |
| Нажатие вне `Button` (элемент дерева, список) | Нет: «pointer simulation is not supported» |
| Выбор элемента `ListBox`/`TabControl` | Скалярный `SelectedIndex` через `set_property`; это проверка привязки, а не выбора мышью |
| Прокрутка и диагностика виртуализации | `scroll`, `get_scrollable_items`, включая переход к индексу |
| Выбор объектного узла `TreeView` | Объектные свойства и `select_item` недоступны |

Следствие: сценарий «книга → глава → сцена → открыть сцену» требует выбора узла дерева и
через MCP не воспроизводится. Этот участок покрыт автоматическим UI-тестом
`EditorAndArchitectureFlowTests.Mvp_flow_creates_structure_edits_text_and_survives_reopen`,
который проходит путь целиком на реальных ViewModel и представлениях.

Дополнительно: сервер обслуживает одно соединение с приложением за раз. Пока приложение
Codex держит подключение, CLI того же сервера к тому же процессу не подключится, и наоборот.

## Известные пробелы

- Автосохранение по таймеру проверяется unit-тестами сервисов, но ещё не проверено
  сквозным сценарием через UI.
- Установка поверх пользовательской Studio и реальная медленная сеть с полным
  установщиком не проверялись; сетевые сбои моделируются автоматическими тестами.
- Сборка/запуск macOS и системный диктор Windows в этой приёмке не проверялись.
- Длительная работа с пользовательской рукописью не заменяется синтетическими тестами.
