Анализ версии 1.1.3.1 — обнаруженные логические и кодовые замечания

Кратко:
- Папка: `1,1,2` содержит `pyproject.toml` с `version = "1.1.3.1"` — рассматривается как релизная (полная) сборка.

Найденные проблемы (приоритезация: быстрые исправления вверху):

1) Переключатель "Высокий контраст" (`cb_high_contrast`) не применяет тему мгновенно
- Где: `src/scriborium/ui/launcher_window.py` (создание чекбокса на строках около 413)
- Симптом: чекбокс и радиокнопки темы влияют на `self.settings`, но при изменении UI меняется лишь после сохранения настроек или при следующем запуске.
- Причина: отсутствует привязка сигнала `toggled` (или `clicked`) чекбокса/радиокнопок к немедленному применению темы. `_apply_theme()` вызывается в `_save_settings()` и при инициализации, но не по переключению.
- Рекомендация: добавить `self.cb_high_contrast.toggled.connect(lambda v: self._apply_theme())` и аналогично для радиокнопок (или отдельный handler, который обновляет `self.settings` и вызывает `_apply_theme()`), чтобы изменения применялись live.

2) Изменение темы не распространяется на уже открытые окна редактора
- Где: `launcher_window._apply_theme()` применяет stylesheet к `LauncherWindow` только.
- Симптом: открытые `EditorWindow` не обновляют свой stylesheet при смене темы в лаунчере.
- Причина: нет механизма рассылки/подписки на изменение темы (есть `event_bus` для языка: `language:changed`, но нет `theme:changed`). EditorWindow при инициализации читает настройки, но не слушает события темы.
- Рекомендация: при сохранении/изменении темы эмитить `event_bus.emit('theme:changed', {'theme':..., 'high_contrast':...})` и подписаться в `EditorWindow` чтобы применять `setStyleSheet(stylesheet_for_theme(...))` на живых окнах.

3) Поведение `stylesheet_for_theme` игнорирует флаг `high_contrast` когда выбрана `classic` тема
- Где: `src/scriborium/ui/theme_styles.py`
- Симптом: при выборе классической темы + флага «высокий контраст» возвращается только классический stylesheet (high-contrast-блок не учитывается).
- Причина: функция сначала проверяет `if t == THEME_CLASSIC: return "...classic..."` и только после этого проверяет `if high_contrast:`. Порядок ветвлений делает комбинацию невозможной.
- Рекомендация: изменить логику так, чтобы high-contrast применялся как наложение (например, если `t == THEME_CLASSIC` и `high_contrast` — комбинировать класический базовый стиль + дополнение high-contrast, либо перейти к приоритету high_contrast перед классикой, если так задумано).

4) Отсутствие реакции UI на смену радиокнопок темы без сохранения
- Где: `launcher_window.py` — радиокнопки `theme_standard` / `theme_classic` не имеют `.toggled.connect(...)` на применение темы.
- Рекомендация: привязать сигнал радиокнопок к live-обновлению темы (как в пункте 1).

5) Мелкие потенциальные ошибки кода (быстрый список для проверки):
- В `theme_styles.py` стоит убедиться, что возвращаемые строковые шаблоны корректно отступлены/не содержат неожиданных управляющих символов (в целом OK).
- В `launcher_window._save_settings()` после изменения `self.settings` делается `self.settings_service.save(self.settings)`; стоит проверить, что `SettingsService.save()` не бросает исключений при отсутствии прав на запись (в логах это может проявиться).

Заключение — статус варианта:
- Папка `lite 1,1,3,1` — это облегчённая сборка (есть `README-LITE.md`, `Scriborium-Lite.spec` и дистрибуция `Scriborium-Lite`).
- Папка `1,1,2` — содержит полную/релизную сборку с `pyproject.toml` и билд-артефактами. Обе папки содержат код версии `1.1.3.1`, но `lite 1,1,3,1` — явный "Lite" образ.
